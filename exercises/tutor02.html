  • 013 is equivalent to decimal 13; In C/C++, this is an octal value.

A variable xy is defined in NASM as follows:

xy:     dw     55h, 66h, 77h

Assume xy starts at address 0x1000. The system uses Little-Endian byte ordering.

What is the word value at address 0x1001?

Step-by-step reasoning for the answer

  • dw 55h → word = 0x0055 → stored as bytes: 55 00
  • dw 66h → word = 0x0066 → stored as bytes: 66 00
  • dw 77h → word = 0x0077 → stored as bytes: 77 00

Memory layout:

0x1005 : 00
0x1004 : 77
0x1003 : 00
0x1002 : 66
0x1001 : 00   ← start reading word here
0x1000 : 55
  • At 0x1001 (LSB) = 0x00
  • At 0x1002 (MSB) = 0x66
  • Word value = 0x6600

The variable val is defined as follows:

val: dw 0x1234

The system is Little-Endian and val is stored starting at address 0x2000. Which two bytes will be stored at addresses 0x2000 and 0x2001, respectively?

Reasoning:

  • dw 0x1234 → word = 0x1234
  • In Little-Endian, least significant byte (LSB) stored at lowest address.
  • LSB = 0x34 → stored at 0x2000
  • MSB = 0x12 → stored at 0x2001

Memory layout:

0x2001 : 12
0x2000 : 34

Given the following data definition:

arr: dd 0x11223344, 0x55667788

and assuming Little-Endian storage starting at address 0x3000, what is the byte stored at address 0x3005?

Step-by-step reasoning:

  • First dword = 0x11223344 → stored as: 44 33 22 11 at addresses 0x3000–0x3003
  • Second dword = 0x55667788 → stored as: 88 77 66 55 at addresses 0x3004–0x3007
  • Address 0x3005 holds byte 0x77 (second byte of second dword).

Memory layout:

0x3007 : 55
0x3006 : 66
0x3005 : 77   ←
0x3004 : 88
0x3003 : 11
0x3002 : 22
0x3001 : 33
0x3000 : 44

Consider the following data section:

section .data
x dd 10
y dd 20

Which of the following instructions correctly loads the value of y into EAX?

  • In NASM, y is a label for a memory location.
  • To load from memory, we must enclose the label in [].
  • mov eax, [y] loads 4 bytes starting from address labeled by y into EAX.

Given the following definitions:

v1 dw -10     ; FFF6h
v2 dw  10     ; 000Ah

On an IA-32 CPU, which instruction(s) loads EAX with 0xFFFFFFF6?

  • -10 in 16-bit signed → 0xFFF6

  • When sign-extended to 32 bits → 0xFFFFFFF6

  • movsx eax, word [v1] → Reads the full 16-bit word, sign-extends to 32-bit → FFFFFFF6 ✅

  • movsx eax, byte [v1] → Reads just the first byte F6 (–10 in signed 8-bit), sign-extends to 32-bit → FFFFFFF6 ✅

  • mov eax, [v1] → load 4 bytes starting from memory labeled by v1, which yields eax = 0x000AFFF6h ❌

  • movzx eax, word [v1] → Zero-extends, producing 0x0000FFF6 ❌

What are the values of AX and BX after executing:

mov ax, 0ABCDh
mov bx, 1234h
xchg ah, bl
  • Initial: AX = AB CD, BX = 12 34 (AH = AB, AL = CD, BH = 12, BL = 34)
  • xchg ah, bl → swap AB ↔︎ 34
  • AX = 34 CD (0x34CD), BX = 12 AB (0x12AB)
