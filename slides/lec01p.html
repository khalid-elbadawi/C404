Everything in a computer is just numbers!

Binary to Decimal Magic ✨

Convert \((01100101)_2\) to decimal

\[1100101_2 = 1×2^6 + 1×2^5 + 0×2^4 + 0×2^3 + 1×2^2 + 0×2^1 + 1×2^0\]

\[= 64 + 32 + 0 + 0 + 4 + 0 + 1 = \boxed{101_{10}}\]

\(01100101_2 \implies 101_{10}\)

Hexadecimal: Programmer’s Best Friend 🔧

Why Hexadecimal?

  • Compact representation
  • Easy conversion to/from binary
  • Natural fit for byte values
  • Used in memory addresses

Quick Reference

Hex Binary Decimal
5 0101 5

Example: \((A13)_{16} = 10×256 + 1×16 + 3×1 = 2579_{10}\)

2’s Complement: Handling Negatives

Step 1: Start with positive number
\(14_{10} = 0000\ 0000\ 0000\ 1110_2\)

Step 2: Flip all bits (1’s complement)

\(1111\ 1111\ 1111\ 0001_2\)

Step 3: Add 1

\(1111\ 1111\ 1111\ 0010_2 = -14_{10}\)

Result: \(-14_{10} = FFF2_{16}\)

BCD: When Precision Matters 💰

Binary-Coded Decimal

  • Each decimal digit = 4 bits
  • Range: 0000 to 1001
  • Used in financial systems
  • Avoids floating-point errors

Example: 176₁₀

Unpacked BCD:

01 07 06  (3 bytes)

Packed BCD:

01 76     (2 bytes)

⚠️ Why? Because 0.1 + 0.2 ≠ 0.3 in floating-point!

🖥️ Intel Processor Evolution

From 8-bit to 64-bit: A Journey Through Time

The x86 Family Tree 🌳

1974 - Intel 8080: 8-bit CPU, 64KB memory

1978 - Intel 8086: 16-bit CPU, 1MB memory, segments!

1985 - Intel 386: 32-bit, 4GB memory, protected mode

1993 - Pentium: Superscalar, MMX, multiple instructions/cycle

2005 - Intel 64: 64-bit addressing, massive memory space

Segmentation: The Original Solution 🧩

Why Segments?

  • Code: Program instructions
  • Data: Variables and constants
  • Stack: Function calls, local vars
  • Extra: Additional data space

Physical Address Formula

Physical = (Segment × 16) + Offset

Example:

CS = 1000h, IP = 0050h
Physical = 10000h + 0050h = 10050h

Today: Mostly handled by the OS, except FS and GS in x64!

Register Specialization 🎯

  • EAX (Accumulator): Multiplication, division, return values
  • ECX (Counter): Loop operations, string operations
  • ESP (Stack Pointer): DON’T TOUCH! (Points to stack top)
  • ESI/EDI (Source/Destination): High-speed memory transfers
  • EBP (Base Pointer): Function parameters and local variables

Rule: ESP and EBP have special jobs - use others for general work!

EFLAGS Register: The Status Reporter 🚩

Key Status Flags

  • CF: Carry Flag (unsigned overflow)
  • ZF: Zero Flag (result = 0)
  • SF: Sign Flag (result negative)
  • OF: Overflow Flag (signed overflow)

Example

mov al, 255     ; AL = 255
add al, 1       ; AL = 0
                ; CF=1, ZF=1

Flags tell you what happened after each operation!

🗺️ Memory Models

How does your program see memory?

Memory Model Evolution 📈

Real-Mode Flat (64KB)

  • Single 64KB block
  • Simple but limited
  • DOS-era programming

Real-Mode Segmented (1MB)

  • Physical = (Segment × 16) + Offset
  • 16-bit segments, 1MB total
  • Complex but more flexible

Protected Mode Flat (4GB)

  • Linear 32-bit address space
  • Modern operating systems
  • OS manages segments for you

Protected Mode: Modern Memory 🛡️

4GB Linear Address Space
0x00000000 ← → 0xFFFFFFFF
OS handles segmentation transparently

Your program sees: One big 4GB memory space
Reality: OS maps this to physical/virtual memory

🔧 Assembly Language Tools

From Human-Readable Code to Machine Instructions

High-Level vs Assembly 🗂️

C/C++ Code

int y = (x + 10) * 3;

Assembly Code

mov   eax, [x]    ; Load x
add   eax, 10     ; Add 10
mov   ebx, 3      ; Load 3
imul  ebx         ; Multiply
mov   [y], eax    ; Store result

One line of C = Multiple assembly instructions!
