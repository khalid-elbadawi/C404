An Assembly Program

Let us consider the following program:

;
;   Adding two numbers
;
      global _main
      
      section .data
sum   dd      0

      section .code
_main:
      mov     eax, 5      ; let eax = 5
      add     eax, 6      ; add 6 to eax
      mov     [sum], eax  ; store result into sum
      
      ret

Assembly Statements

  • An assembly program consists of statements:

    • Instructions: Translated to machine code
    • Directives: Tell assembler to perform special tasks
    • Macros: Shorthand for sequence of statements

  • By default, assembly is not case-sensitive

  • Statement format:

    [label:]     instruction   [operand(s)]   [;comment]

Statement Layout

The layout of source lines

Comments

  • Always start with a semicolon ; and end with newline
  • Example comment structure:
; -----------------------------------------------------------------
; Source name   : addtwo.asm
; Version       : 1.0
; Created date  : 10/4/2020
; Last modified : 22/8/2024
; Author        : Khalid Elbadawi
; Compiling     : nasm -fwin32 addtwo.asm (NASM version 2.15)
; Description   : Store the result of 5 + 6 
; -----------------------------------------------------------------

Program Sections

  • Programs divided into sections representing memory segments
  • Created using section directive:
    • .data: Initialized data items
    • .bss: Uninitialized data items
    • .text: Actual machine instructions

Label Field - User Identifier

  • Programmer-chosen identifier for variables, constants, procedures
  • NASM rules:
    • Maximum 247 characters
    • Start with letter, underscore or ?
    • Subsequent characters: digits, @, #, $, or dot
    • Cannot be reserved word
    • Case sensitive

Reserved Words

  1. Instruction mnemonics (ADD, SUB, MOV)
  2. Register names (EAX, AX, AL, ch)
  3. Directives (DB, DD, SECTION)
  4. Operand attributes (FAR, NEAR, BYTE, DWORD)
  5. Operators used in constant expressions

Reserved words are NOT case sensitive

Instructions

  • Consist of instruction mnemonic followed by operands
  • Operands can be:
    • Explicit: Appear in the statement
    • Implicit: Don’t appear (e.g., EAX in multiplication)
add   eax, [x]    ; x is a label for memory location (variable)
  • First operand: destination operand
  • Second operand: source operand

Instruction Categories

  1. Data movement/transfer instructions
  2. Arithmetic and Logic instructions
  3. Control transfer instructions
  4. Flag control instructions

Defining Initialized Data

Syntax:

[name:]      directive       initializer [, initializer]

Directives:

  • DB: Define BYTE
  • DW: Define WORD
  • DD: Define DWORD
  • DQ: Define QWORD
  • DT: Define TBYTE
  • etc.

Examples:

letter:   db    'A'   ; value is 41h
resp      db    'Y'   ; default user response
num1:     db    -91   ; value is A5h

Multiple Initializers

    db    55h, 56h, 57h   ; 0x55 0x56 0x57
    db    'a', 55h        ; 0x61 0x55
    db    'ab', 13, 10, 0 ; 0x61 0x62 0x0D 0x0A 0x00
    dw    1234h, 5678h    ; 0x34 0x12 0x78 0x56
    dw    12h, 34h        ; 0x12 0x00 0x34 0x00

DUP Operator

Syntax:

[name:]    Dx   <counter> DUP (initializer-list)

Examples:

    db  3 dup(0)      ; db  0, 0, 0
    dw  8 dup(1)      ; dw  1, 1, 1, 1, 1, 1, 1, 1
    db  4 dup('ABC')  ; db  'ABC', 'ABC', 'ABC', 'ABC'

Defining Uninitialized Data

Syntax:

[name:]      RESx       <counter>

Examples:

buffer:   resb    64    ; reserve 64 bytes
list:     resd    100   ; reserve 100 32-bit integers

Defining Constants

Syntax:

name    EQU   <expression>

Examples:

ESC_KEY   equ   27
COUNT     equ   100

Usage:

        mov   eax, COUNT    ; good style
        mov   al, ESC_KEY   ; good style

Current Location ($) and Section Location ($$)

  • $: Current location counter
  • $$: Section location

Example:

myStr:    db    "This is a long string, containing "
          db    "any number of characters."
STRLEN    equ   ($ - myStr)

Addressing Modes

  1. Immediate addressing mode: Operand is a constant expression
  2. Register addressing mode: Operand is a CPU register
  3. Memory addressing modes:
    • Direct memory addressing mode: Constant reference to memory
    • Indirect memory addressing modes: Runtime-determined memory reference

Data Transfer Instructions

  • MOV, XCHG, MOVSX, MOVZX
  • PUSH, POP, PUSHA, POPA, PUSHAD, POPAD
  • CBW, CWD, CDQ, CWDE

MOV Instruction

Syntax:

        mov   <destination>, <source>

Rules:

  • Destination can be register or memory
  • Source can be immediate, register, or memory
  • Both operands must be same size
  • Both operands cannot be memory
  • Instruction pointer cannot be destination

Valid MOV Formats

    mov   reg, reg
    mov   reg, mem
    mov   reg, imm
    mov   mem, reg
    mov   mem, imm    ; must specify size

Example:

    mov   DWORD [x], 5

Memory to Memory Transfer

Single MOV cannot move directly between memory locations

; assign x to y (y = x)
        mov     eax, [x]
        mov     [y], eax

Memory to memory transfer

MOVSX Instruction

Move with sign-extension for signed integers

Variants:

    movsx     reg32, reg/mem8
    movsx     reg32, reg/mem16
    movsx     reg16, reg/mem8

Example:

    movsx     ecx, WORD [v1]  ; ecx = FFFF FFF0h = -16

MOVZX Instruction

Move with zero-extension for unsigned integers

XCHG Instruction

Syntax:

        XCHG    <operand1> , <operand2>

Rules:

  • Both operands must be same size
  • Both operands cannot be memory
  • No immediate operands

Formats:

    XCHG    reg, reg
    XCHG    reg, mem
    XCHG    mem, reg

XCHG Example

        mov     ax, 0A100h
        mov     bx, 0005h
